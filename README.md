# Grade 3 Fund – MAEC

Installable PWA for managing a Grade 3 class fund: parent contributions, expenses, balances, outstanding payments and school celebrations (MVR, calendar-year records).

**Stack:** Cloudflare Pages (hosting) · Pages Functions (`functions/api`) · D1 (database) · R2 (private receipts). No frameworks, no build step.

```
public/      app (index.html, app.js, styles.css, sw.js, manifest, icons, install + offline pages, _headers)
functions/   API – all authentication and role checks happen here, server-side
db/          schema.sql, seed_demo.sql (20 fictional students; generated by scripts/seed_demo.py)
tests/       API tests (node --experimental-sqlite tests/api.test.mjs)
```

## 1. Push to GitHub
```bash
cd grade3-fund-maec
git init -b main && git add . && git commit -m "Grade 3 Fund – MAEC"
git remote add origin https://github.com/<you>/grade3-fund-maec.git   # create a PRIVATE repo first
git push -u origin main
```

## 2. Create the Cloudflare resources (once)
```bash
npm install
npx wrangler login
npx wrangler d1 create grade3-fund          # copy the database_id into wrangler.toml
npx wrangler r2 bucket create grade3-fund-receipts
npm run db:remote                            # creates the tables
npm run db:seed-demo:remote                  # optional: DEMO DATA (remove later from Admin screen)
git commit -am "Set D1 id" && git push
```

## 3. Deploy from GitHub
Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** → pick the repo.
- Framework preset: **None** · Build command: *(empty)* · Build output directory: `public`
- Project name: `grade3-fund-maec`

Then **Settings → Variables and Secrets**: add secret `SETUP_KEY` (a long random string). Redeploy once.
(Bindings `DB` and `RECEIPTS` come from `wrangler.toml`.)

## 4. Subdomain
Pages project → **Custom domains → Set up a domain** → e.g. `grade3.sinfia.net`. Cloudflare creates the DNS record and HTTPS certificate.

## 5. First use
1. Open the site → **First-time setup** → enter `SETUP_KEY`, your email and a password (10+ chars). Setup closes permanently after the first admin exists.
2. **Admin → Create account** for each parent, linked to their child. Share the temporary password privately; parents can change it under **Account**.
3. While **DEMO DATA** is shown, nothing is real. Edit student names under Contributions → Edit, or **Admin → Remove demo data**, then enter real records.
4. Share `https://<your-subdomain>/install.html` with parents.

## How money works
- Stored as integer cents; shown as MVR with 2 decimals. Every figure is calculated from stored records.
- Available Balance = Opening Balance + Contributions received + Other income − Expenses.
- Outstanding = Σ per student max(0, expected − paid in the year). Unpaid amounts are never cash; overpayment does not offset another student.
- Records are never deleted: a mistake is **voided** with a reason and re-entered; every change is in the audit log.
- Year-end: Admin → *Close year* sets next year's opening balance to this year's closing balance (re-runnable).
- Demo and real records are separate (`is_demo`); the app shows only one set at a time.

## Security notes
- Passwords: PBKDF2-SHA256 (100k iterations, per-user salt). Sessions: random 256-bit token, stored hashed, HttpOnly + Secure + SameSite=Strict cookie, 14 days. Login lock after 8 failures / 15 min per email.
- Parents can only read their own child's payments (server-enforced); class totals and the expense list are visible to all signed-in parents; receipts are admin-only and streamed through the API from a private R2 bucket (never public).
- State-changing requests require a same-origin `Origin` header; strict CSP in `public/_headers`.
- Service worker caches only static files; `/api/*` is never cached and offline shows a clear message, never stale figures.
- Recommended: add a Cloudflare **WAF rate-limit rule** on `/api/login`, and enable **D1 Time Travel** (automatic point-in-time restore) plus a periodic `npx wrangler d1 export grade3-fund --remote --output backup.sql`. Keep backups private.

## Hosting cost (verify current limits on Cloudflare's pricing pages before relying on them)
Pages, Pages Functions, D1 and R2 each have a free tier that should comfortably cover a single class (a few dozen users, thousands of records, small receipt files). R2 may require a payment method on file even within its free allowance. The custom subdomain costs nothing extra if you already own the domain. Expected cost for this use: about zero, but confirm.

## Known limits
Payments and expenses are corrected by voiding and re-entering (no in-place edits, by design). PDF reports use the browser's *Print → Save as PDF*. Password reset is done by an administrator (create a new account or ask support to reset in D1). Add a real email-based reset if you need self-service.
